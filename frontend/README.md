# Torment Nexus browser UI

React/TypeScript source and the production `dist/` used by the Rust launcher. The
packaged app serves these files directly; users do not need Node.

## Build and checks

```sh
cd frontend
npm ci --cache ../work/npm-cache --ignore-scripts
npm run build
npm test
PLAYWRIGHT_BROWSERS_PATH=../work/playwright npx playwright install chromium
npm run test:browser
```

`npm run build` typechecks and regenerates `dist/`; rebuild the Rust executable
afterward if its assets are embedded. Production makes no CDN, font, analytics,
or external API requests from the browser.

The Playwright suite starts an **isolated contract fixture**, not real inference,
on `127.0.0.1:47842`. It exercises factory creation and role assignments, immutable
dataset edits, multi-axis mixing, streaming acknowledgements, zeroing, baseline
comparison, cancellation, mix/history reload, chat transcript duplication,
download retry, applied-mixture diagnostics, and small-screen layout. Fixture
state never touches application data and makes no Codex calls. Reports and
screenshots go under `work/`.

These tests complement, and do not replace, the genuine Bonsai/Codex integration
checks described in the project plan. Real GUI checks use the launch URL and
actual durable records, with engine usage coordinated against extraction jobs.

## Boundaries that matter

- The launch token arrives in the URL fragment, is removed immediately, and stays
  in `sessionStorage`. Both API actions and streaming-fetch SSE use an
  `Authorization` header; there is no token query parameter or EventSource URL.
- A 4-second snapshot poll recovers state after disconnection. The atomic
  `output` / `output_token_count` snapshot reconciles zero-based SSE token events
  without duplicating tokens already in a snapshot.
- Vectors and layers are frozen for a running response. Coefficients stay live.
  Slider changes coalesce for 110 ms, requests are serialized, and every request
  carries a complete monotone revisioned snapshot including zeros. Pending does
  **not** mean applied. Only an engine acknowledgement or persisted applied event
  clears pending state.
- Coefficients accept positive, zero, negative, and expanded finite values. They
  describe residual perturbation magnitude, never subjective intensity.
- Applied-mixture geometry is labelled with its acknowledged revision and first
  affected output-token index, never inferred from pending slider positions.
  Layer norms, same-layer direction cosines, and warnings are advisory. Run axis
  badges explicitly show initial coefficients, not a claim about the whole run.
- Baselines retain the exact source transcript, sampling, and raw/template mode;
  the user's draft mix is restored after comparison. Duplicating a chat run keeps
  its entire input transcript, not just its final user message.
- Recipe edits submit a new version. Design, all three writers, review, targeted
  repair, and final dataset are editable. In-flight jobs expose completed
  checkpoints through “Fork completed stage”; a fork creates a separate recipe
  and job, never cancels or mutates the original. Only completed/edited outputs
  enter the picker. Original checkpoint/provenance wrappers remain inspectable.
  JSON validity is checked in the browser; semantic and artifact validation
  remain server responsibilities.
- Text generated by models, agents, or imported records is rendered as text.
  There is no raw HTML or Markdown execution path.
